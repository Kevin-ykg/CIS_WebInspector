# 开发交接入口

本目录面向维护代码的同事；业务汇报材料仍在 `outputs/`。当前流程核对日期：2026-10-28。除明确标为历史记录的章节外，以下均描述**正式编译的当前源码**，不是历史对话中的计划。

## 推荐阅读顺序

| 想了解什么 | 入口 | 看完应能回答 |
|---|---|---|
| 软件做什么、如何构建 | [根 README](../README.md) | 正式程序与 SDK、回归工具有什么区别 |
| 整体算法与参数、修改位置 | [项目全局导航与开发指南](../项目全局导航与开发指南.md) | 从哪一个类/方法进入目标功能 |
| 谁调用谁、哪些事情不应混写 | [职责边界与调用链](职责边界与调用链.md) | 一帧、一段、一个零件分别由谁处理 |
| 图像、坐标、线程、资源 | [数据接口与资源约定](数据接口与资源约定.md) | 图像能否修改、何时释放、尺寸是什么单位 |
| 编译、断点、回归、排障 | [开发调试与验证](开发调试与验证.md) | 如何证明修改没有改变原结果 |
| 最近结构调整与验证范围 | [维护记录](维护记录.md) | 本轮改了什么、哪些尚未实测 |

原生接口逐字段契约见 [Native/README](../Native/README.md)；仅共享二维码给其他项目时，阅读 [二维码 SDK 接入指南](../Native/QR_READER_README.md)。

**要在 C++ `detect` 打断点：**直接阅读 [patch_detector.cpp 断点操作步骤](开发调试与验证.md#在-patch_detectorcpp-的-detect-中打断点)，包含 SDK 检查、原生 Debug/应用构建、PDB、VS 附加、离线触发及空心断点排查。C# Debug 默认仍使用 Release 算法 DLL，不能只按 F5 判断。

## 接手第一天

1. 按构建指南生成原生库和 WPF x64 程序；不要直接编辑 `obj/` 中的生成工程。
2. 确认运行目录的 `app_config.json`、二维码模型、相机 SDK DLL；离线运行也需要工程声明的部署依赖。
3. 选择一份已知图库，配套排版日志及保留 Alpha 的 TIFF/PNG；记录配置、副本路径、输入顺序和代码提交。
4. 从 `MainViewModel.Acquisition → ImageStitcher → InspectionJobRunner` 跟一遍；用日志区分未拼接、跳过、对准失败、零件处理异常、产品 NG。
5. 比较三类最终缺陷与输出图，不把“没有异常”“Completed”“零个结果”当作产品合格的充分条件。

## 自有代码边界

```text
App / Views / ViewModels    WPF 启动、界面和交互
Models                      配置、帧、排版、结果契约
Services                    采集/拼接/作业编排、原生适配、日志与图像输出
Native/include + src        自有 C 接口与 C++ 视觉算法
Native/tests + examples     原生接口/困难码检查及接入示例
Tools                       构建、基线导出/比较、独立回归入口
Regression                  回归规约、迁移验证记录、部分固定样本
docs                        开发交接文档
```

不把 `TLC_SDK_C++_64位/` 厂商源码、`CIS缺陷验证/` 历史实验、`Tools/*Regression/Legacy/` 冻结对照、`bin/obj/` 构建产物或 `outputs/QrReader_SDK/` 发布副本当作正式算法修改入口。发布包应由脚本同步，不能与 `Native/` 各改一份。

## 维护文档的规则

- 改调用顺序：同步职责图与全局指南；改参数/坐标/所有权：同步数据契约。
- 改原生源文件清单：同步 CMake、SDK 打包脚本，并验证交付目录可编译。
- 验证记录写清输入、配置、构建类型、通过项和未覆盖项；历史成绩不能当作本次重新测试。
- 新增说明优先记录“为什么、边界、失败后怎样处理”，避免在各文档复制整段算法说明。
