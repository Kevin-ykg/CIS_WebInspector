# 数据接口与资源约定

返回 [交接入口](README.md)。这些约定比类名更重要；修改它们通常会改变检测结果或引入原生内存错误。

## 1. 图像与坐标链

```text
相机/文件原图
  └─ 数据源 DownscaleFactor 后处理帧（Gray8 / 三通道 BGR）
       └─ 当前帧坐标 + 已处理行数 → 连续采集全局坐标
            └─ 减 SegmentStartGlobalY → 拼接段坐标
                 └─ CIS→排版变换 / 逆向采样 → TIFF/PNG 像素空间
                      └─ 纵向翻转 → 排版裁切空间
                           └─ 减 GlobalRoi 左上角 → 零件原分辨率坐标
                                ├─ 局部配准工作图（宽度最多 700 px）
                                ├─ 普通差分工作图（DefectDetectScale）
                                └─ 细线细节图（scale 限定在 0.5～1）
```

“原分辨率零件”指排版空间裁切尺寸，不是相机传感器的原始像素尺寸。

| 字段/对象 | 正确解释 |
|---|---|
| `StitchedImageResult.Data` | 独立缓冲区，异步预览/保存/检测期间只读；不是可再次填充的相机环形缓冲 |
| `EndQrGlobalY - SegmentStartGlobalY` | 结束二维码在拼接段内的 Y；不能直接拿全局行号索引一段图 |
| `EndQrPixelWidth/Height` | 处理分辨率；常规路径为 X/Y 投影，透视恢复为平均对边长度，沿用既有 ABI |
| `GlobalTransform` | CIS→排版的全局矩阵诊断副本；不能改这份 Mat 来控制原生 Warp |
| `GlobalRoi` | 纵向翻转后的排版大图坐标；局部缺陷框加 ROI 偏移后才可画到全局预览 |
| `OriginalRect / WorkRect` | 零件原尺寸框 / 算法工作图框；不能混用显示尺度 |
| `RelativeTopLeft/BottomRight` | 排版日志物理坐标 mm，按原点偏移及 `LayoutDpi/25.4` 换算 |

`FlipMode.X` 在当前调用中是沿水平轴翻转，即上下翻转。屏幕上的放大、拖动不进入上述坐标链。

## 2. 单位与三类测量

- 排版像素密度：`pixelsPerMm = LayoutDpi / 25.4`。长度乘工作尺度 `scale`，面积乘 `scale²`。
- `DefectToleranceInner/Outer`、`DefectEdgeExclusionThick/Small` 为 mm；前者换算为形态学核尺寸，不能直接当作向单侧膨胀的半径。细小尺寸还受取整、核形状、缩放影响。
- `DefectAreaThreshInner/Outer` 为 mm²，过滤使用连通域实际像素数，不是外接框面积；普通缺陷严格大于换算后的面积门槛才入最终列表。
- 外接框宽/高是紧致**轴对齐**矩形，不是旋转最小面积矩形；绘图框可能带显示余量，不应反算测量值。
- 细线长度来自缺口骨架，线宽来自模板距离场；细线“面积”是断口掩膜非零像素换算值，不能解释为笔画宽度乘断裂长度。
- 汇总中的最大普通候选面积可能非零但数量为零；逐缺陷尺寸明细只列最终通过门槛者。
- `FineLineMinBreakLengthMm` 当前算法最低按 0.5 mm 处理；不能据此宣称所有场景都已达到 0.5 mm 检出能力。

尺度入口见 [patch_detector.cpp](../Native/src/patch_detector.cpp)，结果转换见 [PatchDefectDetector.cs](../Services/PatchDefectDetector.cs)，日志口径见 [Reporting](../Services/InspectionJobRunner.Reporting.cs)。

## 3. 图像所有权与释放顺序

| 边界 | 谁拥有像素 | 调用者必须遵守 |
|---|---|---|
| SDK 回调 → `FrameReadyEventArgs` | 数据源复制后交出托管数组 | 回调返回后 SDK 内存可能复用；不能把 SDK 指针直接排队 |
| `Run` → `cisMat` | `StitchedImageResult.Data` | GCHandle 固定数组；先 Dispose 借用 Mat，再解除固定 |
| 大图 → `new Mat(parent, roi)` | 大图 | 子 Mat 只引用 ROI；父图不能提前释放或并行写入 |
| P/Invoke 输入描述 | C# Mat/数组 | 真实 stride、位深、长度正确；同步调用结束前存活；不跨调用保存指针 |
| 原生输出结果 | C++ RAII + 结果句柄 | C# 在 SafeHandle 作用域内复制；不要从结果取指针后销毁句柄再访问 |
| 全局对准结果 | `AlignmentResult` | `using/Dispose` 释放原生网格和诊断 Mat |
| 模板缓存 | 批次 `PatchSiftTemplateCache` | worker 全部退出后释放；特征发布后只读；哈希相同仍需逐像素比较 |
| UI 结果图 | 独立 JPEG 字节/冻结 BitmapImage | WPF 对象在 Dispatcher 创建或 Freeze 后跨线程传递 |

[LayoutImage](../Services/InspectionJobRunner.LayoutImage.cs) 先提取 Alpha 再合成白底。合成成功后替换并释放旧图；取消/异常由局部 finally 和外层 Run finally 协作释放。预览方法仅修改副本。

C ABI 为 Windows x64、cdecl、pack=8，传固定宽度字段/指针/stride，不跨边界传 Mat、STL 或异常。二维码 v2、Alignment v1、Patch v1；独立 QrReader 为另一套 v1。布局校验失败应报错，不能用历史 C# 算法静默兜底。详细见 [Native 接口契约](../Native/README.md)。

## 4. 并发与取消不是一回事

| 对象 | 当前策略 | 修改风险 |
|---|---|---|
| OrderedFrameProcessor | 有界顺序消费；满队列触发停采保护 | 多消费者会破坏全局行数和拼接状态 |
| BoundedImageSaveQueue | 保存单独有界排队 | 保存失败不等于业务图像已检测；不能改成无界队列 |
| InspectionJobCoordinator | 最新作业优先，取消旧任务，Semaphore 串行大图计算 | 并非每段必检；若需全检必须另行设计业务背压 |
| PatchCropper | 零件 Parallel.ForEach；每 worker 独占 SIFT/Matcher | 不能跨 worker 共享可变特征器 |
| TemplateCache | 短目录锁 + 单桶锁；桶内创建模板 | 禁止持有目录锁等待桶锁，避免与桶内统计路径互锁 |
| WPF | Dispatcher 更新绑定和预览 | 后台直接创建未冻结依赖对象可能跨线程异常 |

取消在阶段边界检查，不会强制中断一次正在执行的原生运算；取消后旧计算可能暂时继续占 CPU。模板缓存命中数量/结果列表顺序可能受调度影响，比较算法结果应按 PartId/ROI，而不是日志行顺序。

## 5. 配置与输出约定

配置文件在程序目录。采集会话和检测作业各自取 `CaptureSnapshot` 深拷贝；`AppConfig` 仍是可变类，只是运行期间按只读使用。修改设置不应改变已开始的作业。旧像素配置由 `ConfigManager` 按单位标识迁移；不要重命名 JSON 字段或重复换算。

`SaveCroppedImages` 控制作业诊断图片落盘，不关闭 UI 预览，也不关闭运行日志或聚合性能 CSV。采集帧自动保存另有设置，不是同一个开关。

| 结果 | 含义与注意点 |
|---|---|
| `<PartId>_alpha.png` | 原零件尺寸上按 Alpha 阈值二值化；不等同于先缩放后阈值的普通工作图 |
| `<PartId>_cis.jpg` | 局部对准后、最终 CIS 阈值生效的预览；JPEG 可能出现压缩灰边，不应回读作真值 |
| `<PartId>_edge_exclusion.png` | 工作尺度屏蔽图用 Nearest 映回零件尺寸；保持分辨率不意味着轮廓厚度无量化误差 |
| `GlobalTiffReference.jpg / GlobalCisDefectResult.jpg` | 独立全局预览，可能缩小至最大高 3000；不是原尺寸算法输入 |
| `WhiteInk_BottomMarks_Preview.jpg` | 独立白墨标注副本；白墨检测先于排版关联 |
| `AlignmentMarks_*.jpg` | Mark 定位诊断；核对搜索带、编号与匹配情况 |
| `PerformanceBaselines.csv` | 聚合性能观察；不控制判定，也不受作业图片开关关闭 |

**数据缺失必须显式解释：**无排版资料会返回 Skipped；无 Alpha 当前可能返回 Completed 但零件结果为空。应核对“排版零件数、实际结果数、处理异常数”而非只看失败数量。本轮没有改变这一行为。
