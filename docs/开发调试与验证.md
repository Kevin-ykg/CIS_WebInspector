# 开发调试与验证

返回 [交接入口](README.md)。命令均从项目根目录执行；路径含空格时使用引号。

## 1. 构建的唯一源头

- 应用：[CIS_WebInspector.csproj](../CIS_WebInspector.csproj)，.NET Framework 4.8 / WPF / x64。
- 原生：[Native/CMakeLists.txt](../Native/CMakeLists.txt)，C++17 / OpenCV + contrib 4.10.0 / IPP。
- 准备 VS 的 .NET 桌面及 C++ 桌面工作负载、.NET 4.8 开发目标包、CMake；部署需要对应 VC++ x64 运行库。
- Volans 引用及原生 DLL 从工程指定的相对位置复制；TLC DLL/CameraLink 驱动由设备环境提供。本轮不修改厂商 SDK。

```powershell
powershell -ExecutionPolicy Bypass -File Tools/Build-VisionNative.ps1 -Configuration Release
dotnet restore CIS_WebInspector.sln
dotnet build CIS_WebInspector.sln --no-restore -c Debug -p:Platform=x64
dotnet build CIS_WebInspector.sln --no-restore -c Release -p:Platform=x64
```

首次原生构建下载固定版本 OpenCV 并校验归档，时间/空间开销较大。之后只改自有 C++ 时可复用缓存：

```powershell
cmake --build obj/VisionNative/core-build --config Release --parallel 2 -- /p:UseStructuredOutput=false
dotnet build CIS_WebInspector.sln --no-restore -c Debug -p:Platform=x64
```

第二步会复制新 DLL。只保存 cpp 或只构建 C#，不会自动重编 C++。不要修改生成的 vcxproj；新增文件必须进入 CMake。删除 obj 可以重建，但其中测试输出/尚未导出的基线不能再凭代码还原。

## 2. 断点应该打在哪里

| 问题 | 第一组断点 | 下一组 |
|---|---|---|
| 帧没有进入检测 | MainViewModel.Acquisition 的 OnFrameReady / ProcessQueuedFrame | ImageStitcher.ProcessOwnedFrame |
| 二维码不识别 | QrCodeDetector.Detect | CisQrAdapter::detect → QrDetector::detect → 对应策略函数 |
| 拼接后没有产品结果 | InspectionJobRunner.Run 的提前返回 | Reporting 的状态原因；配置/排版/Alpha |
| 大图对不齐 | ImageAligner.ComputeTransform | alignment_global.cpp / alignment_marks.cpp |
| 零件对不齐或误检 | PatchCropper ROI；PatchDefectDetector.Detect | patch_detector.cpp::detect → local_align / fine_line |
| 全局图标记不对 | PatchCropper.Preview.cs | GlobalRoi、OriginalRect、显示比例 |

混合调试步骤：

1. 构建原生 Debug：`Tools/Build-VisionNative.ps1 -Configuration Debug`。
2. C# 用 `-p:VisionNativeConfiguration=Debug` 构建，并在 VS 启用本机代码调试。
3. 将同一次构建生成的 `obj/VisionNative/core-build/Debug/CISVisionCore.pdb` 放到实际 DLL 旁或加入符号路径；当前项目复制规则只自动复制 DLL。
4. 在“调试 → 窗口 → 模块”确认加载的 DLL 路径和 PDB 匹配。断点空心时先查旧 DLL/未加载符号，不要随意改算法。
5. 打开 CMake 生成的原生解决方案或直接打开 Native 的 CMake 项目，便于 C++ 索引。仅把 cpp 当杂项文件打开，导航可能只认识已打开文件。
6. 逐零件调试可临时设置 `DefectMaxParallelism=1`；这不关闭相机/保存/UI 线程，也不等同于 OpenCV 内部全局单线程。测性能前恢复原配置和 Release。

C# Debug 默认仍链接 Release 算法 DLL，这是当前部署策略；其优化后的原生断点可能跳行。

## 4. 常见故障定位

| 表现 | 先确认 |
|---|---|
| 找不到 CISVisionCore.dll | 是否先构建原生、C# 是否复制到正在启动的目录 |
| BadImageFormat / EntryPointNotFound | x64 是否一致，是否混入旧版 ABI |
| 没有白墨/缺陷图片 | 两个功能开关、SaveCroppedImages、输出路径和作业状态 |
| Completed 但结果数为零 | Alpha 是否存在、ROI 是否为空、是否全为 QRCode 辅助区域 |
| 调参数没有作用 | 改的是否实际运行目录配置、是否仍在使用旧会话/作业快照 |
| 更高并行度反而慢 | 内存带宽、图像编码、磁盘、原生算子并行叠加，而非只看 CPU 核数 |
| 缺陷面积与框面积不同 | 正常：面积来自真实连通域/断口掩膜，框包含背景 |
| SDK 与正式程序 QR 不同 | 核心是否同版本、CIS ROI/保护带/极性是否不同；静态例程必须重新链接 |

## 5. 安全修改步骤

新增配置先修改 AppConfig、设置 VM/XAML、快照传递、P/Invoke 映射和 C ABI；改变 ABI 字段需同步版本/size 检查和原生侧，不能只改其中一端。已有单位迁移必须保持兼容。

修改算法：固定正负样本 → 保存原输出 → 一次改一个因素 → 对比最终缺陷/坐标/图像 → 再测热机耗时和内存。性能比较需同并行度、同保存策略并分开首次加载，不把迁移前后测试中偶然更快的单次耗时作为本轮结构拆分收益。

修改职责/注释：优先保持表达式、遍历顺序、插值、参数、锁、取消/异常边界不变；使用现有回归证明等价。历史 Legacy 不随当前实现一起修改，否则对照失去意义。
