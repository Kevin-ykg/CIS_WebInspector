# 统一局部配准与 0.6 mm 缺陷：第一轮隔离优化进展

状态更新：**下文第 1～3 节为最初离线原型记录；正式 C++/C# 统一流程已构建并复制到 Debug/Release 输出，但尚未经用户完整实图库验收。现场 `app_config.json` 未修改。** 下列实验结果不等于产线能力声明。

## 1. 配准门控改动和实测

[离线原型](run_offline.py)保留“同一组特征匹配→相似/仿射估计→统一门控”的主线，新增两项防错：

1. 轮廓评价由模板→实拍的单向距离，改为**双向九区距离**。多出来或落在错周期位置的实拍结构不再被单向低分掩盖。轮廓仍只评价，不产生或精修矩阵。
2. 用 RANSAC 内点做空间留区重拟合：逐次移除一个有证据的九宫格区域，检查全件四角和中心预测位移；最大变化超过 **6 原像素**的候选拒绝为 `SpatialModelInstability`。人工点只在候选确定后评价，不参与此门控。

冻结的 8 件/87 组确认点结果见 [机器报告](offline-result-stability-20261024.json)：

| 样本 | 当前离线结果 | 人工点观察 P95，原像素 | 关键观察 |
|---|---|---:|---|
| img2/04200… | 待复核 | 105.6 | 特征/内点不足；不能强行接受。 |
| img2/2b728… | 待复核 | 59.4 | 相似候选局部区域明显退化；保留拒绝。 |
| img2/3b728… | 仿射候选 | 6.7 | 明显改善，但接近人工配对误差量级，非几何认证。 |

同一输入重复运行，去掉耗时字段后状态、矩阵、内点及人工点评价完全一致。另试过统一灰度 SIFT 输入，8 件仅 2 件获得候选（其中 3b… 的 P95 7.8px）；Lowe ratio 统一放宽到 0.80 也未解开两件失败零件，且有样本变差；工作密度从 3 提到 5 px/mm 后耗时近乎翻倍而准确性未整体改善。因此这三项参数试验都**没有**进入保留的统一流程。当前原型没有针对错周期竞争解建立独立证据，不能声称重复纹理风险已解决。Python 单件耗时不能与生产 C++ 同条件比较。

## 2. 0.6 mm 检测链路隔离测试

新增 `Tools/PatchRegression/SensitivityChecks.cs`，由 `PatchRegression.exe <项目根目录> --sensitivity-06` 运行；用现场配置的只读快照建立理想二值图，在 `300 DPI` 下将 `0.6mm` 栅格化成 **7 原像素**方块/断口。局部配准关闭以分离缺陷阈值因素；现场参数文件不写回。[完整结果](../../../obj/PatchNativeValidation/sensitivity-06-20261024/sensitivity.json)保存了每个配置快照与计数。

| 隔离配置 | 0.6mm 内缺失 | 0.6mm 外多墨 | 无缺陷对照 |
|---|---|---|---|
| 现场原参数 | 未检出 | 未检出 | Pass |
| 仅将内外面积阈值改为 0.15mm² | 未检出 | 检出 | Pass |
| 再将内外容差/屏蔽置零，保持 0.3 倍 | 检出 | 检出 | Pass |
| 同上，改 0.5 或 1 倍 | 均检出 | 均检出 | Pass |

说明：内部 0.6mm 缺失不仅受 2mm² 面积阈值限制，也会被当前 2mm 内部容差抹平；外部 0.6mm 多墨在该合成位置主要受 4mm² 面积阈值限制。**这不表示建议把现场容差设为零。** 真实轻微错位和噪声下，零容差会引发边缘误检。理想细线断口在隔离配置中目前仍作为内部缺陷报出，而不是第三类细线；细线目标尚未完成。

本轮 Debug x64 构建零错误、零警告；隔离合成检测执行完毕。正式替换尚需：真实且经测量的 0.6/0.8/1.0mm 内/外及细线正负样本、精度高于当前约 3px/侧的局部几何基准、稀疏件和重复周期竞争解处理、真实裁框变化和并行度 1/4/8 重复性、同机 C++ 耗时比较。不能用“拒绝更多候选”代替正确接受率，也不能用理想合成图推断真实产线漏误检率。

## 4. 正式实现接入与当前验证（后续更新）

- `PatchCropper` 的默认 15mm 真实搜索余量与理论核心分离；4mm 在 300DPI 下仅约 47px，无法覆盖近期重复纹理样本的百像素位移。C ABI 升至 v2，结构化读取 `Applied/NotNeeded/Review/Error`、模型、匹配/内点和质量指标。可信矩阵仅对核心灰度采样一次；三类缺陷阈值、面积和细线规则未变。
- C++ 只编入 `patch_local_align.cpp` 一条配准流程（原文件名 `patch_unified_alignment.cpp`）；同一组 SIFT 匹配分别估计相似和受约束仿射。先前的轮廓平移、半量相似和距离场矩阵精修不再参与正式 DLL。九区评分重用模板边缘距离场，减少重复计算。
- RANSAC 的 8 原像素阈值只用来构造候选内点，**不是**允许最终错位 8px；后续 RMS、留区稳定性和九区轮廓仍全过门控。与之独立的周期复核保持 3 原像素尺度。试过 3/4.5 原像素候选阈值，会把少特征的 img3/Y62/042… 一并拒绝；当前选择仍须真实图库检查错周期风险。
- 8 个冻结 ROI（仅用**人为常量边框**补齐上下文的独立诊断，绝非正式实拍验收）中，3b…、img3/Y62 的 042…、ed18… 得到局部候选；img2 的 042…、2b…、4b…、5b… 与 d73… 标记待复核。4b/5b 的低内点比例、d73 的最差分区残差不再因平均轮廓改善而被接受。该拒绝策略仍需用户实图库检查正确接受率。
- 用相同合成像素进行 65 次共同平移/留白变化，配准状态一致，归一化矩阵的最大投影差约 `1.3e-13 px`；这验证坐标等变性，**不验证**真实纹理下的裁切稳定或最终缺陷精度。
- C++ Debug/Release、WPF Debug/Release x64 构建通过；C ABI 17 项（含核心/搜索区尺寸）、托管流水线 20 项通过。旧算法逐像素等价工具返回 MISMATCH 是预期的算法变化，不得写为等价通过。0.6mm 合成测试仍表明当前现场阈值无法保证检出，绝无“已达到 0.6mm”结论。

用户验证重点：用同一 `app_config.json` 重放 img/2、img/3、17-13-15 等整批图库，核对 Applied/Review 数、局部对齐、已知三类真实缺陷是否保留、误检以及并行度 1/4/8 的重复性；同数据同保存条件比较节拍/P95。若正确目标过多被 Review 或耗时超 20%，当前版本仍需继续调优，不应作为最终上线验收。

## 5. 2026-10-25：配准警示与产品判定解耦

按现场使用反馈，`Review/Error` 不再阻断三类缺陷的正常统计和显示。零件仍使用全局对准裁图继续检测，按现有阈值计入 Pass/NG、尺寸日志与全局类别框；同时保留配准原因、匹配/内点、黄色 `ALIGN?` 提示。处理异常仍不算产品 NG，不能和配准质量警示混同。批次 `CompletedWithReview` 表示有配准警示，产品结论仍按实际缺陷计数给出。

合成流水线新增 `NG+配准警示`、`Pass+配准警示` 两类回归；均验证警示与正常产品结论及可视化并存。该改动只调整业务结果语义，不改变 C++ 配准模型和三类缺陷阈值；配准警示件仍应人工核对是否存在错位误检或漏检。
