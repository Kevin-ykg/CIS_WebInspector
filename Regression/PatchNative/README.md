# 零件局部配准与三类缺陷 C++ 迁移验证

核对日期：2026-09-07。迁移前基准为本次工作开始时的源码，Git HEAD：`d67c96994ee16177094d1b314d10feb9f3f257ca`。

## 结论与范围

迁移目标是封装、内存所有权和复用，不是换算法。C# 保留裁切、作业调度、保存和结果汇总；局部配准、阈值、普通差分、边缘屏蔽、连通域、细线证据链和物理测量进入同一个 `CISVisionCore.dll`。配置文件没有被改写。

当前实际配准代码包含轮廓快速平移、SIFT/RANSAC 相似变换、边缘小范围精修、质量门控及内点平移后备。本次全部按当前代码迁移，**没有按早期对话替换当前算法**。注释保留原方法名、关键门槛的原因和物理语义，并补充 C++ RAII/锁/结果读取说明。

### 耗时观测（不含保存图）

先预热，再交替 C#/C++ 次序，每个实现各运行 6 次，单 worker、同一缓存生命周期、不落盘。该段测量启用细线、最短 0.5 mm，其他值沿用该套配置（最大线宽仍为运行配置的 15 mm）。

| 真实零件 | 迁移前中位耗时 | C++ 中位耗时 | 说明 |
|---|---:|---:|---|
| `ff11e72effdf472699781f9d2b0e9046` | 1293.80 ms | 1227.98 ms | 同一输入、预热后顺序测试 |
| `c7d5d1c7e9af4890b69d99b06b558d2b` | 793.35 ms | 716.14 ms | 同一输入、预热后顺序测试 |

两个样本有改善，但样本少且运行环境负载会波动。完整对比中仍有个别调用 C++ 更慢；**不将这些单件数字外推为整条产线提速比例**。原 OpenCvSharp 本来就在原生层计算，语言迁移不保证统一加速。

并发重复记录的是进程 Private Bytes，包含托管堆、缓存和 OpenCV 分配器保留。此次短测不足以证明无内存泄漏；现场长时间、多批次、取消/重启压力测试仍需进行。

## 如何复现

```powershell
dotnet build Tools/PatchRegression/PatchRegression.csproj -c Debug -p:Platform=x64

& 'Tools/PatchRegression/bin/x64/Debug/net48/PatchRegression.exe' (Get-Location).Path `
  --frames 'E:/南京爱速智/CIS/Defect batch test/12-16' --output production-12-16

& 'Tools/PatchRegression/bin/x64/Debug/net48/PatchRegression.exe' (Get-Location).Path `
  --frames 'E:/南京爱速智/CIS/moreMarks/6细线断裂修改阈值' `
  --layout-log 'E:/南京爱速智/CIS/moreMarks/log/2026-06-24/Debug.log' `
  --tiff-dir 'E:/南京爱速智/CIS/moreMarks/tiff' --row-spacing 920 --layout-height 1000 `
  --output fine-line-6
```

在以上命令附加 `--actual-only`，并更换 `--output` 目录名，即运行 v3 原配置对比。工具不修改正式配置、不连接相机、不启动 WPF 检测任务。

- 详细临时图和完整矩形结果：`obj/PatchNativeValidation/<output>/`。
- 本目录 JSON：保留结果摘要、两端配准诊断、有效配置、耗时、并发和接口检查，避免长期提交大图/构建缓存。
- C# 冻结基准：`Tools/PatchRegression/Legacy`，只在独立工具编译；正式工程显式排除，不能改成线上兜底分支。
- 以后优化算法时保持冻结基准不变；确认要接受行为变化后另立基线，不能边改正式实现边改旧实现让结果“相等”。
