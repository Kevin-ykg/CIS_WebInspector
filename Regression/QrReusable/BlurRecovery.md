# 模糊二维码局部恢复验证（2026-09-22）

## 输入与原因

用户原图 `C:\Users\EDY\Desktop\test1.png`（1125×1035）及 `test2.png`（1233×1176），均完整 BGR 输入通用识别器，默认黑色前景、Y 尺度 1。

- 修改前两张均未识别；原始 Otsu 轮廓未提取出可靠的嵌套定位框。
- 模板搜索可找到三个定位框，但旧透视恢复的固定朝向模块检查及几何近似不足以覆盖这两张失焦图。直接放宽结构检查或继续枚举亮度/尺度也未解码。
- test1 在定位框确定的局部红通道图中可读；test2 的顶部定位框与底部定位框边界变形不同，三个中心点外推/单一透视还存在采样偏差。根据三个定位框的十二个实测外边界角点拟合局部逆映射后成功。

## 正式改动

新文件 `Native/src/qr_blur_local.cpp`；常规路径、旧恢复路径顺序不改，在 `blurred` 最后追加：

1. 复用已确认的最多两个三定位框组合，不重新全图搜索。
2. 自动局部裁图及有限工作尺寸重采样，先尝试原像素红通道解码。
3. 必要时对三个定位框局部 Otsu 轮廓测量，筛选大小/中心/凸四边形合格的外边界。
4. 用实测边界拟合二次平滑逆映射，检查拟合误差、采样范围和 Jacobian，拒绝翻折/过大尺度变化。
5. 实拍灰度仅重采样一次，检查定位框/时序图案，再补静区交给 WeChat 解码。

新增分支最多 4 次解码；不是把所有预处理跑一遍。C++ RAII 管理局部 Mat；C ABI、C# 接口、CIS 安装 ROI、拼接和其他视觉算法均不改。成功坐标回到调用方输入图，局部逆映射输出几何是模型估计的平均对边长度，不作为精密计量保证。

```powershell
.\obj\QrReaderBuild\Release\QrReaderRecoveryChecks.exe .\Assets\WeChatQRCode 'C:\Users\EDY\Desktop\test1.png' 'C:\Users\EDY\Desktop\test2.png'
```

测试程序中的期望文本仅用于断言，不参与算法，也不随生产程序启动。原始图片仍在用户提供的路径，不将其文本/文件名嵌入算法。SDK 例程可直接传入同样图片路径，不必改源码。

## 明确边界

- 只确认当前两张原图成功，并非保证所有失焦、反光和形变二维码都能识别。额外旋转试验中 test1 的 90° 版本成功、180° 版本仍失败；不以降低几何门槛或无限枚举来掩盖该限制。
- 第四角无定位框，局部形变只能有限外推；几何可信不等于每个数据模块都准确，所以最终必须由解码器确认，失败不返回猜测文本。
- 此恢复需要足够的三个定位框边界；大面积缺失、过曝丢失模块、极强非线性变形仍可能失败。硬件清晰度和照明仍然重要。
- 没有用这两张图推导业务文字模板，也没有将用户给出的正确文本传给解码器。
